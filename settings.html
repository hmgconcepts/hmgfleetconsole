🟢 Google Drive backup — your blueprint, implemented off

No extra Supabase project needed. Register projects on any device → they auto-back-up to your own Google Drive (a hidden app-data folder only this console can see — never your real Drive files). On a new phone: sign in → Connect Google Drive → 📥 Restore → continue monitoring. The OAuth Client ID ships in the repo (assets/js/gdrive-config.js — safe to commit: a web Client ID is public by design and locked to your site's URL by Google's Authorized JavaScript Origins), so nothing needs to be typed on new devices.

⚙️ One-time setup needed (≈5 min, once for the whole company): create a free Google Cloud OAuth Client ID and paste it into assets/js/gdrive-config.js. The complete click-by-click recipe is in that file's header and on the Deployment page (Phase 4c). After committing, this card shows the Connect button on every device automatically.

Rotation keeps the newest 5 backup generations. Restore merges (union by project URL / incident id) — it can never delete or overwrite local work. Drive backup and ☁️ Cloud Sync below are independent; use either or both.

☁️ Cloud Sync — same fleet on every device off

Without sync, each browser keeps its own fleet list. Turn this on and every device that unlocks the same vault sees the same projects, incidents, history and settings — automatically (pull on open, push ~8 s after any change). End-to-end encrypted: data is sealed with AES-GCM-256 in your browser before upload (key derived from your passphrase, PBKDF2 · 210k iterations); the vault only ever stores unreadable ciphertext and the passphrase never leaves your devices. Uses one FREE Supabase project owned by HMG as the vault.

🔑 Login credentials (username & password)

The console login lives in one file: assets/js/auth-config.js. Type your new details below — this generator produces the complete replacement text for that file (the password itself is never stored, only its salted SHA-256 hash). Then in GitHub: open assets/js/auth-config.js → ✏️ Edit → select all → paste → Commit. Vercel redeploys automatically (~1 minute) and the new login is live everywhere.


        
        
⚠️ Test the new login in a private/incognito window BEFORE closing your signed-in session, so a typo can never lock you out.

      

    


    

      
🔐 Console PIN (optional)

      
A courtesy screen-lock for shared machines: pages ask for this PIN once per browser session. It is stored only as a SHA-256 hash. This is not cryptographic security — real security is the fact that only public anon keys are ever stored, and RLS on each project seals all business data. Requires HTTPS (or localhost); on plain HTTP the PIN feature stays off.
