🚀 Deployment RunbookEvery step, every click, every gotcha — from ZIP to fully-armed fleet monitoring, first-user ready without assistance

What you are deploying: a folder of static files (HTML/CSS/JS + PNG icons). No build step, no npm, no server, no database of its own, no AI API. Any static host serves it; we use GitHub (storage + keep-alive robot) and Vercel (hosting) because both are free and you already use them for clients.

Time: ~20 min Phases 1–3 · ~2 min per client in Phase 4 · ~7 min optional Drive backup (Phase 4c) · Phase 5 optional hardening. Cost: ₦0.

💡 Two new V1.9 features affect deploy: (1) login page now has 👁️ show/hide password toggle (WCAG) — no extra step, but documented for first users; (2) project registration now asks billing model — 💎 One-time / lifetime vs 🔁 Subscription — so you don't have to set a renewal date for one-time clients (field hides automatically). One-time clients own forever and never appear in renewal alerts.

  • ✅ Vercel account (free Hobby), signed in with GitHub
  • ✅ The hmg-fleet-console.zip unzipped — must contain: index.html, login.html, projects.html, incidents.html, reports.html, board.html, status.html, compare.html, tools.html, selftest.html, guide.html, deploy.html, about.html, settings.html, sw.js, manifest.json, README.md, assets folder (css/js/img), tools folder, and hidden .github folder

Phase 1 — Put console online (GitHub + Vercel)

1
Create GitHub repository. github.com/new → Owner: you → Name: hmgfleetconsole (or hmg-fleet-console) → Visibility: Private ← NOT optional. Public exposes auth-config.js (login hash — crackable offline) and lets anyone clone your ops console. Already public? Settings → General → Danger Zone → Change visibility → Private. Do NOT add README from wizard → Create repository.
2
Upload files. Empty-repo page → "uploading an existing file" → select everything inside unzipped folder → drag onto upload area → Commit.
⚠️ GitHub drag-and-drop skips dot-folders, so .github/workflows/fleet-keepalive.yml will be missing — step 3 fixes it. If you push with git, dot-folders upload fine and step 3 unnecessary.
3
Add workflow file by hand. Repo → Add file → Create new file → name exactly .github/workflows/fleet-keepalive.yml → paste contents from ZIP → Commit. Verify: Actions tab lists "Fleet keep-alive".
4
Deploy on Vercel. vercel.com → Add New… → Project → Import repo → Framework Preset: Other, Root ./, Build/Output empty → Deploy. URL e.g. https://hmgfleetconsole.vercel.app. Every commit auto-redeploys. Alternatives: Netlify drag-and-drop, GitHub Pages (private needs paid plan — Vercel doesn't). file:// works as preview but login/PIN need HTTPS.

Phase 2 — First login & change password (DO NOT SKIP) — includes show/hide toggle

5
Sign in with shipped defaults. Open Vercel URL → redirected to sign-in. Enter 
Username: hmgadmin
Password: ChangeMe#2026
The password field has an eye button 👁️ — click it to show/hide what you typed (WCAG 3.3.8 accessible-auth: screen readers can't read hidden password text, and eye toggle reduces typos — especially on phones). Tick "Keep me signed in" on own machines → Dashboard.
6
Generate YOUR credentials. ⚙️ Settings → 🔑 Login credentials → type new username + strong password (12+ chars, mix words/digits/symbols, not reused) — both fields have 👁️ show/hide buttons. Click ⚙️ Generate file text → 📋 Copy. Password itself never appears in generated text — only salted SHA-256 hash.
7
Commit new credentials. GitHub → assets/js/auth-config.js → ✏️ Edit → select all → paste → Commit. Vercel redeploys ~1 min. Verify safely: incognito window → URL → sign in with NEW credentials. Only after success, close incognito. Existing session keeps working through change, so typo can never lock you out while you have a signed-in tab. After commit, the red security banner (V1.5) disappears automatically.
8
Optional: session PIN. Settings → 🔐 Console PIN — extra once-per-session lock for shared machines, with its own 👁️ toggle.

Phase 4 — Register fleet — includes billing model (one-time vs subscription)

12
Collect each project's two values. Every registration needs Supabase URL + anon key:
  • HMG products (School Connect / Tutoring / Drama / CBT): open client site's config — e.g. https://gosaportal.vercel.app/assets/js/config.js → copy SUPABASE_URL + SUPABASE_ANON_KEY.
  • Other Supabase: Supabase dashboard → Project Settings → API → Project URL + anon public key.
⚠️ NEVER service_role key — console detects and refuses it; key inspector tells you what any key is.
13
Register each project — choose billing model. 🗂️ Projects → fill Name, URL, anon key → Type (decides subscription verdict probe) → site URL (reachability + deploy detection) → Environment → Billing model *:
  • 💎 One-time payment / lifetime — client paid once, owns forever. When selected: renewal date field hides automatically (no date needed), renewal alerts skip it, renewal calendar excludes it, license cell shows lifetime, revenue KPI sums Amount field, cost ledger tracks it. Example: School Connect sold for one-time ₦150k — select one-time, enter 150000 in Amount.
  • 🔁 Subscription — renewal date matters. When selected: renewal date field shows — set it (e.g. next term), fee note, amount if you track it. Console counts down, alerts inside warning window (default 14 days, configurable), calendar sorted soonest-first with phone, server verdict via sc_license_status RPC. Even expired subs stay pause-proof (license-independent keep-alive).
Also fill Group/org (e.g. HMG Schools), SLO target % (default 99.5 — error-budget tracking), Tags, client contact, Amount, fee note, Runbook (incident steps shown on Status page), Notes → ➕ Add & test. Within seconds: health score + SLO + keep-alive green + deploy version if site URL given.
Reading first result: ✓ pinged just now = perfect · RPC missing = non-HMG needs step 14 · unreachable = wrong URL or paused (restore in Supabase dashboard, then ⚡).
Bulk import: 📥 Bulk CSV import → pick CSV (columns: name,url,key,type,site,env,billing,group,tags,client_name,client_phone,client_email,renewal,amount,fee_note,slo,runbook,notes — billing=onetime or subscription; when onetime renewal ignored). Template download button in form details.
14
Non-HMG projects only: add keep-alive endpoint. 🧰 Ops Toolkit → Keep-alive SQL → 📋 Copy → that project's Supabase → SQL Editor → Run ("Success. No rows returned" correct) → console row ⚡ → green. Idempotent, touches only heartbeat table.
15
Switch on automation + first backup. Dashboard → tick 🤖 Auto-pilot. Settings → 🔔 Desktop notifications (allow prompt) + optional webhook alert URL (Discord/Slack/Telegram — free push to phone with console closed, test button). Ops Toolkit → ⬇ Download full backup → save JSON to Google Drive. Console reminds if backup 14+ days old. Dashboard → 🚀 Detect deploys to populate deploy history for sites.

Phase 4c — 🟢 Google Drive backup & restore (complete walkthrough Parts A–D)

What you get: every project auto-backed-up to your own Google Drive (hidden app-data folder — never visible files). On ANY new phone/laptop: sign in → Connect → 📥 Restore → all projects appear and you continue monitoring. Nothing typed on new devices because Client ID ships in repo. Total setup ~7 min, once, for whole company. Filenames carry project count (…-p12.json), restore skips empty generations (V1.8 fix), 📚 View backups lists every generation with per-file restore/delete — School Connect pattern fully adopted.

Part A — Create Google Cloud project (steps 15e-1 … 15e-4)

1
Open Google Cloud Console. console.cloud.google.com → sign in with HMG Google account (each user backs up to THEIR OWN Drive; Cloud project only issues Client ID). First visit: accept terms.
2
Create project. Top bar project dropdown → NEW PROJECT → name HMG Fleet → No organization → CREATE → wait ~10s, ensure dropdown shows HMG Fleet.
3
Enable Drive API. ☰ → APIs & Services → Library → search "Google Drive API" → ENABLE. Skipping causes "Google Drive API has not been used in project…" at backup time.
4
Configure OAuth consent screen. ☰ → APIs & Services → OAuth consent screen: User Type External → CREATE → App name "HMG Fleet Console", your email → Save. Scopes page: Save. Test users — important: + ADD USERS → your Gmail + every HMG staffer → ADD → Save.
💡 Why test users? Status stays Testing forever — up to 100 users, NO verification review, works immediately. Never need to publish. If user sees "Access blocked: … has not completed verification", add Gmail to Test-users list, retry, no redeploy.

Part B — Create OAuth Client ID (steps 15e-5 … 15f)

5
Create credential. ☰ → APIs & Services → Credentials → + CREATE CREDENTIALS → OAuth client ID: Type Web application → Name "Fleet Console Web" → Authorized JavaScript origins → + ADD URI → EXACTLY your deployed URL with https, NO trailing slash, e.g. 
https://hmgfleetconsole.vercel.app
(copy from browser address bar, delete trailing /). Add custom domain later same way. Redirect URIs empty → CREATE → copy Client ID (…apps.googleusercontent.com). Ignore secret — app never uses one.
6
Commit Client ID (one file edit). GitHub → assets/js/gdrive-config.js → ✏️ Edit → paste into CLIENT_ID: '' → Commit. Vercel redeploys ~1 min. File served network-first, so installed copies pick it up next load.
🔒 Safe to commit: web OAuth Client ID is public by design (every Google Sign-In site exposes theirs). Google only honours it from whitelisted origins (step 5), so stranger can't use from own site. Console requests only drive.appdata scope — hidden folder private to this app inside each user's OWN Drive: cannot see real files. No client SECRET exists in this architecture. Keep repo Private anyway (holds login hash).

Part C — Connect, back up, restore (steps 15g)

7
Connect main device. Console → Settings → 🟢 Google Drive backup (now shows Connect button) → 🔗 Connect → Google popup → pick account → consent screen lists one permission ("See, edit, create and delete its own configuration data in your Google Drive" — hidden app folder) → Continue. Shows Connected as you@gmail.com, auto-backup ON, first backup uploads immediately (if fleet non-empty — empty fleets never auto-backed-up, V1.8 fix).
8
Verify backup exists. Click 💾 Back up now → toast "Backed up to Google Drive (hmg-fleet-backup-…-p12.json)" with project count in name. Card last-backup updates. File lives in hidden app-data area — NOT visible in drive.google.com by design. Proof = restore test step 10.
9
Optional: encrypt backups. Same card → backup passphrase (8+ chars) — future backups sealed with AES-GCM-256 before upload, passphrase required at restore. Write somewhere safe: encrypted without passphrase unreadable by everyone including Google. Field has 👁️ toggle.
10
New phone / laptop / reinstalled browser — restore flow.
  1. Open console URL → sign in (eye toggle helps on phone — tap 👁️ to check typing).
  2. Settings → Google Drive backup → 🔗 Connect → SAME Google account.
  3. Click 📥 Restore from Drive (newest non-empty auto) or 📚 View backups → see every generation with date, size, project count (…-p12) → Restore THIS on specific one, Delete strays (e.g. empty). Toast reports restored N project(s)… merged, not overwritten.
  4. Dashboard — every project there with notes, tags, billing (💎 vs 🔁), group, renewal dates, SLO, runbook, incident journal, history. Continue monitoring.
Restores MERGE (union by URL / id / timestamp): never deletes local work. This device also auto-backs-up after changes (~20s debounce), rotation keeps newest 5.

Phase 5 — Hands-off keep-alive layers (closed-tab protection)

Do at least ONE. Each alone prevents 7-day pause.

16
Layer A — GitHub Actions (recommended first; already in repo).
  1. Ops Toolkit → Copy secret value (one URL per line, live from fleet).
  2. GitHub repo → Settings → Secrets → Actions → New secret → Name: FLEET_TARGETS → paste → Add.
  3. Test: Actions tab → Fleet keep-alive → Run workflow → every line OK 200.
Runs every 2 days forever. Fleet changed → regenerate + edit secret. Red run + email on failure = free alarm.
17
Layer B — cron-job.org. Free account → Create cronjob → URL: 📋 keep-alive URL → POST → every 3 days → Save → Run now test (200). Repeat per project. Enable failure notifications = second alarm.
18
Layer C — UptimeRobot. Free account → HTTP(s) monitor → URL: keep-alive URL and/or live site → 5 min → email alert. External vantage point + third alarm + optional public status pages.

Updating console later

  1. Edit files (GitHub web or git push). Vercel redeploys.
  2. If HTML/CSS/JS changed: bump CACHE in sw.js (e.g. hmg-fleet-v1.9-…-10 → -11) so installed copies refresh offline cache.
  3. Exceptions network-first: auth-config.js + gdrive-config.js — login + Drive Client ID changes take effect next online load without version bump.
  4. Fleet data never touched by updates — lives in browser (and Drive/vault).

Stronger login alternatives (optional, still free)

Built-in login (salted-hash + throttle) blocks casual visitors. For server-enforced auth: Cloudflare Access (Zero Trust — free ≤50 users):

  1. Add domain you control to Cloudflare (free), e.g. fleet.hmgconcepts.com, point at Vercel deployment (Vercel → Settings → Domains → add hostname; CNAME Cloudflare shows).
  2. Cloudflare dashboard → Zero Trust → Access → Applications → Add application → Self-hosted → domain = hostname.
  3. Policy: Allow → Emails → your email(s). Login method One-time PIN (no extra accounts).
  4. Now every visit must pass Cloudflare checkpoint (email OTP) BEFORE console served. Built-in login remains second layer.

Vercel password protection simplest but paid tier — Cloudflare Access free equivalent stronger. Fail-safe: console holds only public anon keys; client data sealed by RLS.
